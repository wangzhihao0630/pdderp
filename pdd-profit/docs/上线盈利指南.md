# 上线与盈利指南

配套主文档：`README.md`（二次开发手册）。这份文档只讲三件事：**怎么发布上线、怎么定价、怎么把第一批用户拉进来**。

---

## 一、发布上线：推荐方案

### 方案对比

| 方案 | 月成本 | 难度 | 数据可控 | 适合阶段 |
|---|---|---|---|---|
| **A. 轻量服务器 + 宝塔**（推荐） | 60~120 元 | 中 | ⭐⭐⭐⭐⭐ | 打算长期做、要备案域名 |
| **B. 云托管 Render/Railway** | 0~50 元 | 低 | ⭐⭐⭐（需挂盘） | 试水验证、不想碰运维 |
| **C. 国内云函数 + 静态托管** | 几元 | 高 | ⭐⭐ | 不推荐，改造成本高 |

> 结论：**先用方案 B 花 0 成本验证有没有人付费，跑通后迁到方案 A 长期经营。**

---

### 方案 A：轻量服务器 + 宝塔（约 30 分钟）

1. **买服务器**：腾讯云/阿里云「轻量应用服务器」，2 核 2G、40G SSD、带宽 3~5M，新用户首年约 60~100 元。地域选离用户近的。
2. **装环境**：服务器选型直接选「宝塔面板」镜像，或在系统里执行宝塔官方一键安装脚本。
3. **传代码**：宝塔 → 文件 → 上传 `pdd-profit` 整个文件夹到 `/www/wwwroot/pdd-profit`（或 `git clone`）。
4. **起服务**：宝塔 → 软件商店 → 安装 **PM2 管理器 / Node 项目** → 添加项目：
   - 启动文件：`server.js`
   - 端口：`3000`
   - 环境变量：`DATA_DIR=/www/wwwroot/pdd-profit/data`
5. **反向代理**：宝塔 → 网站 → 添加站点 → 反向代理到 `http://127.0.0.1:3000`。
6. **HTTPS**：站点设置 → SSL → Let's Encrypt 免费证书，开启强制 HTTPS（**支付页必须 HTTPS**，否则浏览器会拦）。
7. **域名与备案**：国内服务器 + 国内域名必须 ICP 备案（约 7~20 天，免费）。不想等备案就用中国香港/海外服务器 + 域名直接解析，但微信内打开可能被拦截。
8. **自动备份**：宝塔 → 计划任务 → 每天打包 `/www/wwwroot/pdd-profit/data` 到对象存储或另一台机器。

---

### 方案 B：云托管（约 10 分钟，可白嫖验证）

本项目已带 `Dockerfile` 和 `render.yaml`，以 Render 为例：

1. 把代码推到 GitHub 仓库（注意 `.gitignore` 已排除 `data/`，不要提交用户数据）。
2. Render → New → Blueprint → 选择仓库，自动识别 `render.yaml`。
3. **必须挂载持久卷**：`render.yaml` 里已配置 1GB 磁盘挂载到 `/app/data`，不要用免费无磁盘方案（重启丢数据）。
4. 部署完成后访问 `https://xxx.onrender.com/admin.html`，先改密码。

> 免费档通常 15 分钟无访问就休眠，首次打开要等 30 秒左右。验证期能接受，正式做建议升级到付费档（约 $7/月）或迁移到方案 A。

## 二、定价：怎么定才有人买

### 参考定价（已在系统里预置，可直接在后台改）

| 套餐 | 价格 | 折合每天 | 定位 |
|---|---|---|---|
| 体验周卡 | 19.9 元 | 2.8 元 | **引流款**，降低首次付费门槛 |
| 月度会员 | 59 元 | 1.97 元 | 主力款，80% 用户会选这个 |
| 季度会员 | 149 元 | 1.66 元 | 提客单价 |
| 年度会员 | 399 元 | 1.09 元 | 现金流款，前期可当锚点 |

### 定价的 4 条原则

1. **锚定效应**：把年卡放在最显眼位置（哪怕没人买），月卡会显得便宜得多。
2. **先低后高**：冷启动期把月卡压到 39 元换第一批真实付费用户 + 口碑，有了 100 个付费用户再涨到 59~79 元。老用户按原价续费，不要得罪早期用户。
3. **算清楚用户的账**：你的定价要让用户觉得"少亏一单就回本"。一个每月投 1 万推广费的商家，用你的工具把投产比从 2.0 优化到 2.3，多赚 3000 元，59 元对他毫无压力。**在销售文案里一定要写这个对比**。
4. **24 小时免费试用不要改长**：太长了没人付费，24 小时足够体验完整价值，又留着紧迫感。

### 收入测算（保守）

| 付费用户数 | 月卡 59 元为主 | 月收入 |
|---|---|---|
| 50 人 | — | ≈ 2,950 元 |
| 200 人 | — | ≈ 11,800 元 |
| 500 人 | 含 20% 季/年卡 | ≈ 35,000 元 |

成本几乎只有服务器 + 域名（<150 元/月），**毛利率 95% 以上**。这门生意的关键不在成本，在流量。

## 三、拉新：你的用户在哪

目标人群非常集中：**拼多多商家（尤其是做全站推广/多多搜索的新手卖家）**。

### 免费渠道（优先级从高到低）

| 渠道 | 具体做法 |
|---|---|
| **抖音/快手短视频**（首选） | 拍"屏幕录制算账"类内容：输入一组真实数据 → 算出某商品其实在亏钱 → 给出优化建议。这类"帮你发现自己亏钱"的内容完播率极高，挂小号微信或评论区引导 |
| **小红书图文** | 标题模板：《拼多多投产比多少才不亏钱？一张表算清楚》《别再按毛利算利润了，你漏了退货运费》。图文放计算截图，主页挂链接 |
| **拼多多卖家群 / 电商交流群** | 直接发"免费算利润"的工具链接，不要硬广，用"我做了个算账工具，大家试试准不准"的姿态 |
| **知乎/贴吧/公众号** | 回答"拼多多怎么算利润""全站推广投产比多少合适"类问题，文末留工具 |
| **SEO** | 首页的标题和描述已经包含"拼多多利润计算器/净投产比"关键词，服务器跑起来后百度会自动收录，长期有自然流量 |

### 付费渠道（有了付费用户再考虑）

- 抖音「巨量千川」投「电商工具」兴趣人群，日预算 100 元起测
- 找拼多多中小卖家粉丝量的博主做一口价推广（500~2000 元/条），先谈 CPS 分成

### 转化率关键：漏斗别漏

```
访问 → 注册（领取 24h）→ 真正用一次计算器 → 觉得有用 → 到期被拦截 → 付费
```

每一环都会掉人，两个最有效的优化：

1. **注册后立刻算一次**：在注册成功页直接引导跳到计算器并预填一组示例数据，让他 10 秒内看到结果。没用过工具的人 100% 不会付费。
2. **到期拦截页要"疼"**：现在到期后是弹提示跳转充值页，建议在充值页顶部加一句"你的会员已于 X 月 X 日到期，续费后立即可继续测算"——损失厌恶比收益更能促使付费。

## 四、功能迭代路线（按 ROI 排序）

| 优先级 | 功能 | 为什么 |
|---|---|---|
| P0 | **保存历史测算记录**（用户可回看/对比） | 让用户产生"存了数据"的迁移成本，续费率直接上一个台阶 |
| P0 | **一键导出测算结果为图片** | 天然的传播素材，用户会主动发到群里 = 免费裂变 |
| P1 | **多商品对比表**：一次算 3 个品，横向选哪个能推 | 从工具升级为决策工具，客单价可翻倍 |
| P1 | **推广预算反推**：我想日赚 500，需要投多少 | 高感知价值功能 |
| P2 | **邀请返利**：老用户邀请注册，双方各得 3 天 | 低成本裂变 |
| P2 | **优惠券码**：节日促销、社群发放 | 灵活的促销手段 |
| P3 | 手机验证码登录、微信扫码登录 | 降低注册门槛 |

> 每加一个功能，按 `README.md` 第四节的步骤做，都是"加一个页面 + 加一个接口"的量级。

## 五、从收款码升级到官方支付接口（重要）

现在用的是**收款码 + 人工核对**，优点是今天就能上线、零资质门槛；缺点是规模上来后你会被核对工作淹没，而且**个人收款码用于经营性收款本身存在被风控限额的风险**。

建议的升级节点和路径：

1. **月收入 < 3000 元**：收款码模式够用，每天花 5 分钟核对。
2. **月收入 3000~1 万元**：去办一张**个体工商户营业执照**（多数地区可线上办、免费），用它申请支付宝/微信的**商家收款码**，费率约 0.38%~0.6%，可正常经营性收款。
3. **月收入 > 1 万元**：申请**微信支付商户号 / 支付宝当面付**（需营业执照 + 备案域名 + 对公或法人账户），换成 `Native 扫码支付`：
   - 后端加一个 `/api/pay/create` 接口，调微信统一下单拿到 `code_url`，前端生成二维码
   - 再加一个 `/api/pay/notify` 回调接口，收到支付成功通知后直接给用户加时长（**真正的自动到账**）
   - `server.js` 里的订单表结构不用改，加一个 `payType: 'official'` 字段即可
   - 这个改造量约 200 行代码，可以等真正需要时再做

## 六、风险与合规（务必看完）

1. **不要承诺收益**。工具定位是"算账"，不是"保证赚钱"。首页和公告里避免出现"稳赚""必盈利"等表述。
2. **计算结果仅供参考**。已在页脚标注，建议保留，避免用户按结果决策亏损后产生纠纷。
3. **经营性收款要合规**。见上一节，规模上来后务必办执照、走商户号。
4. **隐私与数据**：你存了用户的账号密码哈希，务必保管好 `data/db.json`，不要提交到公开代码仓库；如果面向大量用户，建议在页面加一份简版《用户协议》和《隐私政策》。
5. **域名备案**：用国内服务器就一定要备案，否则随时可能被阻断解析。
6. **数据备份**：用户和订单是你唯一的资产，丢了就全没了。至少做到每天一次自动备份，且备份不在同一台机器上。

## 七、第一周的行动计划

| 天 | 动作 |
|---|---|
| Day 1 | 本地跑起来 → 用手机体验全流程 → 换上自己的收款码、公告、客服微信 |
| Day 2 | 部署上线（方案 B 或 A）→ 改管理员密码 → 自测一笔完整充值 |

| Day 6 | 根据反馈修 1~2 个最被吐槽的点（通常是输入项太多或看不懂某个词） |
| Day 7 | 复盘：注册数、试用后付费率。付费率 > 3% 就继续加码推广；< 1% 先改落地页和免费体验流程，别急着投钱 |
